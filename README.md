# Операционные системы — практические работы № 1–8

Учебный проект по курсу «Операционные системы», часть 3А. Все работы выполнены по **варианту B** и объединены в один репозиторий.

**Репозиторий:** <https://github.com/mikikyn/os-course>  
**Основная среда:** Ubuntu / WSL, Bash, Python 3  
**Ветка:** `main`

## О проекте

Проект последовательно охватывает основные механизмы операционной системы:

- пользователи, группы и права доступа;
- Bash-скрипты и системные вызовы;
- процессы, потоки и копирование при записи;
- планирование процессора;
- синхронизация и состояние гонки;
- межпроцессное взаимодействие;
- предотвращение, избегание и обнаружение взаимоблокировок.

Каждая работа находится в отдельном каталоге, запускается одной командой и содержит собственный `README.md` с описанием, реальными результатами запуска и выводами.

## Структура репозитория

| Каталог | Тема | Что реализовано |
|---|---|---|
| `pr01/` | Пользователи и права | Группа `developers`, общий каталог `/srv/shared`, режим `2775`, проверка наследования группы и прав на удаление |
| `pr02/` | Bash и системные вызовы | Формирование отчёта по логам, обработка аргументов и ошибок, трассировка через `strace` |
| `pr03/` | Процессы | Дерево процессов через `/proc`, `fork/exec/wait`, zombie, orphan, copy-on-write |
| `pr04/` | Потоки и процессы | Сравнение CPU-bound и I/O-bound задач, влияние GIL, демонстрация общей памяти |
| `pr05/` | Планировщики CPU | FCFS, SJF, SRTF, приоритетный планировщик, Round Robin, aging, график зависимости от кванта |
| `pr06/` | Синхронизация | Race condition, mutex, семафоры, condition variable, bounded buffer, barrier, lost wakeup |
| `pr07/` | IPC | FIFO, Unix domain sockets, Pipe и shared memory, передача 10 миллионов чисел |
| `pr08/` | Deadlock | Алгоритм банкира, wait-for graph, `TrackedLock`, обедающие философы |

Подробные инструкции и фактический вывод находятся в `README.md` соответствующей работы.

## Требования

Рекомендуемая среда — Ubuntu 22.04 или новее, в том числе Ubuntu под WSL.

Необходимые программы:

- Python 3.11+;
- Bash;
- Git;
- `strace` для ПР-2;
- `timeout` из GNU coreutils для ПР-8;
- `unzip` для распаковки учебных архивов.

Внешние Python-библиотеки не требуются: используется стандартная библиотека.

Установка системных зависимостей:

```bash
sudo apt update
sudo apt install -y python3 git strace coreutils unzip
```

Клонирование репозитория:

```bash
git clone https://github.com/mikikyn/os-course.git
cd os-course
```

## Быстрый запуск

Из корня репозитория любую работу можно запустить отдельно:

```bash
bash pr01/run.sh
bash pr02/run.sh
bash pr03/run.sh
bash pr04/run.sh
bash pr05/run.sh
bash pr06/run.sh
bash pr07/run.sh
bash pr08/run.sh
```

Скрипты самостоятельно переходят в каталог своей работы, выполняют проверки, сохраняют результаты и обновляют локальный `README.md`.

> ПР-1 запрашивает `sudo`, поскольку создаёт учебных пользователей и настраивает системный каталог. ПР-4 выполняет ресурсоёмкие замеры. ПР-8 содержит два намеренно зависающих сценария, которые автоматически останавливаются через `timeout`.

## Краткое описание работ

### ПР-1 — пользователи, группы и права доступа

Создаются пользователь `student2` и группа `developers`. Общий каталог `/srv/shared` получает владельца `root:developers` и права `2775`:

- `2` — setgid, поэтому новые файлы наследуют группу каталога;
- `7` — владелец может читать, изменять и входить в каталог;
- `7` — члены группы имеют те же права;
- `5` — остальные могут читать содержимое и входить в каталог, но не изменять его.

Отдельно проверяется, что возможность удалить файл определяется правом записи в **каталог**, а не только правами на сам файл. Опасный режим `chmod 777` не используется.

### ПР-2 — Bash-отчёт и трассировка системных вызовов

`report.sh` анализирует логи, поддерживает фильтрацию по уровню и ограничение количества записей, проверяет аргументы и существование каталога. Для воспроизводимого запуска автоматически создаются тестовые логи.

`strace` показывает, какие системные вызовы выполняет программа: открытие файла, чтение и закрытие дескриптора. Полная трассировка сохраняется в `trace.txt`, а `analyze_trace.py` выделяет операции, относящиеся к выбранному файлу.

### ПР-3 — процессы и их состояния

Реализованы:

- чтение дерева процессов напрямую из `/proc`;
- запуск нескольких дочерних процессов через `fork` и `exec`;
- ожидание завершения через `waitpid`;
- демонстрация zombie до вызова `wait`;
- демонстрация orphan и его усыновления другим процессом;
- copy-on-write после `fork`.

Для COW сравниваются `Shared_Dirty` и `Private_Dirty` из `/proc/<pid>/smaps_rollup`: после изменения памяти ребёнком общие страницы копируются и становятся частными.

### ПР-4 — потоки против процессов

На CPU-bound задаче сравниваются потоки и процессы, а на I/O-bound задаче выполняются параллельные обращения к локальному HTTP-серверу. Для каждого замера используются три повторения и медиана.

Основной вывод:

- в CPython потоки ограничены GIL при интенсивных вычислениях на чистом Python;
- процессы имеют отдельные интерпретаторы и могут использовать несколько ядер;
- во время ожидания I/O GIL освобождается, поэтому потоки эффективно параллелят сетевые запросы;
- процессы не делят обычную память напрямую, а потоки работают в общем адресном пространстве.

Большой файл `numbers.txt` создаётся локально и не отправляется в Git.

### ПР-5 — алгоритмы планирования CPU

Единый симулятор принимает набор процессов и возвращает список интервалов выполнения. Реализованы FCFS, SJF, SRTF, вытесняющий приоритетный планировщик и Round Robin.

Для алгоритмов рассчитываются:

- среднее время ожидания;
- среднее время полного выполнения;
- время первого запуска;
- последовательность выполнения процессов.

Эталонный набор `set1.txt` проверяется автоматически. Отдельно строится `rr_sweep.png` — зависимость среднего времени ожидания от кванта Round Robin. Сценарий `starve.txt` показывает голодание длинного низкоприоритетного процесса и улучшение его времени первого запуска после включения aging.

### ПР-6 — синхронизация потоков

Показана потеря обновлений при неатомарном увеличении общего счётчика и её устранение с помощью mutex.

Ограниченный кольцевой буфер реализован двумя способами:

1. на семафорах;
2. на условной переменной.

В обоих вариантах три производителя и два потребителя обрабатывают 1000 уникальных элементов. Проверяются отсутствие потерь, дубликатов, переполнения и зависания. Дополнительно реализованы многоразовый барьер и демонстрация lost wakeup, объясняющая, почему `wait()` необходимо вызывать в цикле `while`, а не в `if`.

### ПР-7 — межпроцессное взаимодействие

Один вычислительный сервис реализован через:

- два именованных канала FIFO;
- Unix domain socket.

FIFO обслуживает клиентов последовательно, а socket-сервер принимает несколько одновременных клиентов. Арифметические выражения разбираются через AST без небезопасного `eval`.

Затем сравниваются Pipe и `multiprocessing.shared_memory`: передаются одинаковые 10 000 000 целых чисел, занимающие 40 000 000 байт. Shared memory позволяет читать общие страницы без отправки полной копии через канал. После завершения FIFO, socket и сегмент разделяемой памяти удаляются.

### ПР-8 — взаимоблокировки

Алгоритм банкира вычисляет `Need = Max − Allocation`, проверяет наличие безопасной последовательности и выполняет запросы только если после временного выделения состояние остаётся безопасным. При отказе изменения откатываются.

Детектор строит граф ожидания и ищет цикл поиском в глубину. `TrackedLock` обнаруживает цикл до фактической блокировки и выбрасывает управляемое исключение вместо зависания.

Задача философов представлена в трёх режимах:

- `naive` — намеренный deadlock;
- `ordered` — предотвращение через глобальный порядок захвата ресурсов;
- `waiter` — не более четырёх философов одновременно за столом.

Код `124` после намеренно зависших сценариев означает срабатывание `timeout` и является ожидаемым результатом. Исправленные режимы завершаются с `meals=[20, 20, 20, 20, 20]`.

## Результаты и артефакты

После запуска сохраняются реальные результаты конкретной системы:

- отчёты и замеры в `results.txt` и файлах результатов;
- трассировки системных вызовов в ПР-2;
- график `rr_sweep.png` в ПР-5;
- обновлённые README с выводами в каждой работе.

Времена выполнения могут отличаться на другом компьютере. Это нормально: важны методика измерения, контрольные суммы, инварианты и сопоставимость условий эксперимента.

Большие сгенерированные данные, кэши Python, временные IPC-файлы и другие служебные артефакты исключены через `.gitignore`.
